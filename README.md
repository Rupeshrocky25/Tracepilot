# TracePilot

TracePilot is a light-only, futuristic bluish liquid-glass browser-based coding workspace. Open a local project, explicitly choose whether to send the current file as context, request a code proposal, and review each diff before writing it. There is no application backend. This build is a coding workspace; it does not implement the earlier incident-investigation workflow.

## Start

```sh
npm install
npm run dev
```

`npm test` runs the automated suite. `npm run build` performs TypeScript checks and creates a production build. There is no dedicated lint script configured.

## AI providers and models

Use **Providers** in the application to add credentials with a label. Credentials are held in React memory for this tab only. They are not written to localStorage, sessionStorage, IndexedDB, cookies, environment variables, analytics, or application logs. Removing a credential clears it from the active app state; closing or refreshing the tab clears all credentials. A credential/model must pass a direct connection test before chat requests can use it. Test status is in memory and is not persisted.

The default and required Nebius runtime is **Nebius Token Factory** using its OpenAI-compatible chat completions API at `https://api.tokenfactory.nebius.com/v1/chat/completions`. The app sends the user's bearer key directly from the browser. The model catalog includes `nvidia/Nemotron-3_5-Lightning`, `nvidia/Nemotron-3-Ultra-550b-a55b`, `nvidia/Nemotron-3-Nano-30B-A3B`, and `nvidia/Nemotron-3.5-Super-VL`. Availability, account permissions, limits, and exact model IDs may change; a successful test with the user's key is the app's gate before use. Nebius documents Token Factory inference as OpenAI-compatible at [Nebius inference overview](https://docs.tokenfactory.nebius.com/ai-models-inference/overview) and publishes its current NVIDIA models at [Nebius NVIDIA Nemotron inference](https://nebius.com/services/token-factory/models/nvidia-nemotron-models-inference).

The NVIDIA API Catalog is also available as a separate direct provider adapter at `https://integrate.api.nvidia.com/v1/chat/completions`, currently using the documented `nvidia/nemotron-3-super-120b-a12b` model ID. Selecting NVIDIA does not route requests through Nebius. Providers are kept distinct, and the app does not claim Nebius eligibility merely because a model is named Nemotron or is used through another provider. The Nebius adapter is a hosted Token Factory inference API, not a Nebius AI Cloud VM deployment. NVIDIA documents its hosted completion endpoint, bearer authentication, and SSE streaming in its [NIM API reference](https://docs.api.nvidia.com/nim/reference/nvidia-nemotron-3-super-120b-a12b-infer).

For Nebius Token Factory, **Test connection** calls its documented `GET https://api.tokenfactory.nebius.com/v1/models` endpoint and uses the returned IDs to populate the selector for that credential. This verifies catalog/authentication access only; **Test inference** separately makes a minimal chat-completions request and checks for the requested confirmation phrase. NVIDIA currently uses its configured model catalog because a model-list endpoint is not implemented there. Chat responses stream directly into the conversation. Completed turns retain provider, model, HTTP status, elapsed time, and returned token usage in the local conversation record; only the total is shown in the UI when present. Providers that omit usage leave it unavailable. The app does not send tool schemas or execute model-requested tools. Model capability is not treated as an enabled TracePilot tool.

To manually verify live Nebius inference, start TracePilot, open **Providers**, add your own **Nebius Token Factory API key** (do not paste it into a project file, terminal command, or chat), select **Nebius Token Factory**, click **Test connection**, select a returned model ID, then click **Test inference**. A passing inference test requires HTTP success, valid chat-completions JSON, and the confirmation phrase. Then send a normal prompt with that tested model and confirm the streamed assistant response and request metadata. The browser sends the bearer key directly to `api.tokenfactory.nebius.com`; browser CORS/network errors are surfaced and never proxied. This workspace currently has no configured provider credential, so live inference remains unverified here.

Browser calls are direct. Keys exist in renderer memory and are sent only to the selected provider. This avoids persistence and a TracePilot credential proxy, but browser-memory keys are not protected from malicious scripts executing in the same page (for example, an XSS flaw or compromised dependency). This browser build has no trusted local inference gateway or desktop main-process credential boundary. If that threat model is unacceptable, use a hardened local gateway only after reviewing its disclosure and explicit credential-forwarding design; this app does not silently proxy keys. If a provider rejects credentials, lacks CORS support, hits a rate limit, or is unavailable, the app displays recovery guidance. No developer key or default key is included. This workspace has no configured provider credential; tests use mocked fetch responses and do not establish live access.

Prompts go to the selected provider after the user sends. Source content is sent only after both the include checkbox and confirmation dialog. The prompt treats source as untrusted input. Proposed changes are constrained to the exact file explicitly supplied in that request; the app displays a diff and requires explicit approval. The app does not execute shell commands, run project tests, or invoke model-requested tools. It therefore cannot verify a proposed code change by running relevant tests; only the browser file write is verified by reading the exact file back, which does not establish code correctness. Project context is currently limited to the file the user explicitly includes; cross-file retrieval and task-specific model routing are not implemented.

## Local files and persistence

In browsers supporting the File System Access API, the user-initiated folder picker opens a local project. File contents are read when a file is opened. The app excludes `.git`, dependency, and build folders from browsing and limits text files to 1 MB. A read-only file chooser fallback is available when folder access is unsupported. File handles remain in memory and must be reopened after refresh.

Editor changes in a writable File System Access session are saved automatically one second after the last edit. The editor reports unsaved, saving, saved, and failed states. A successful save is reported only after the selected file is read back and matches the written contents. Save also works with Ctrl+S (or Cmd+S). If the browser requests permission, grant it to save; denied permission, unavailable access, disk errors, and external edits are reported while keeping the editor text. External changes are detected before writing to avoid overwriting them. Leaving with unsaved content first attempts a save and then asks before discarding if saving fails. Closing or refreshing with unsaved changes uses the browser's before-unload prompt. Line endings and an existing UTF-8 BOM are preserved when practical. The file chooser fallback is read-only.

User-created project and conversation records are stored locally in IndexedDB. Conversation order, titles, message order, provider/model metadata, and message timestamps are retained. Conversations can be renamed or deleted individually after confirmation; deletion updates only that conversation record and does not remove project folders or files. API keys, project file contents, directory handles, and provider test results are not persisted. No sample incidents, conversations, fake metrics, or demo records are seeded. Clearing site data deletes local conversation records. Browser storage can be cleared or evicted by the browser, so export/backup is not currently available.

## Scope and security

TracePilot is a coding workspace in this repository, not a finished incident-response product. It has no incident import, deterministic incident diagnostics, source-linked incident hypotheses, incident persistence, or actual test-based incident verification. It does not label AI output as a proven root cause.
